# 首次配对交付条件

本页针对旧自定义运行时（Legacy）。新增 Sunshine 路线复用上游的主机端 PIN 页面，见 [Sunshine 首次使用](sunshine-quickstart.md)；该新路线已完成源码与夹具验证，实际安装和首次配对仍待实机验收。

截至 2026-11-07，旧运行时的产品源码和本地控制台具备部署、检查、启停与诊断功能，但没有已验证的主机端配对入口。运行时公开契约只规定启停、supervisor与文件布局，没有规定如何接收、确认、取消或撤销新的配对请求。因此本页是尚待补齐的交付条件，不是已经可执行的配对操作手册。

## 当前链路的断点

Moonlight 能发现主机、serverinfo 返回成功、界面显示“就绪”，都不能证明该客户端已经配对，也不能说明主机具备可用的首次配对确认方式。客户端显示 PIN 后，还需要主机侧完成协议规定的确认。当前控制台不接收 PIN，不读写配对凭据，不导入证书。

[第二客户端验收](remote-client-test.md) 和历史 Mac/电视盒记录验证的是特定环境中的已配对客户端；这些记录不能替代新用户在干净安装上的首次配对证据。未提供主机侧入口时，不应让新用户反复点击主机图标等待配对成功。

## 运行时供应方需要提供的公开接口

请为拟发布的同一运行时版本提供以下资料，不需要提供任何私钥、证书样本、真实 PIN 或现有配对数据库：

| 项目 | 需要说明的内容 |
|---|---|
| 支持范围 | 运行时版本、产品版本范围、支持的 Moonlight 平台与版本 |
| 主机端入口 | 真实存在的官方界面或受支持的本机接口；权限、启动方式与生命周期 |
| 配对确认流程 | 谁显示 PIN、谁输入 PIN、何时允许确认；如何关联当前待确认的客户端请求，避免误配其他设备 |
| 等待与取消 | 超时、用户取消、客户端断开、主机重启、连续请求和重复提交的确定行为 |
| 状态结果 | 等待、成功、失败、过期等结果的结构和错误含义；成功需来自运行时，不是用户点击按钮即算成功 |
| 解除配对 | 精确撤销单个客户端的方式、失败结果与边界，不批量清除其他客户端 |
| 信息保护 | PIN不写日志/URL/配置；密钥保留在所属端；控制台不读取、导出或展示私钥 |
| 可复现实例 | 合成数据的请求/响应示例，以及干净环境中从未配对到可串流的验证步骤 |

产品侧拿到真实接口后，才能确定是打开已有主机配对工具，还是在本地控制台中增加适配器。本文不预设不存在的 API 地址、脚本名或命令参数，也不将普通 Windows 证书导入当作通用 Moonlight 配对流程。

## 最小交付验收

以下各项必须绑定同一源码版本、MSI与运行时版本；记录只保留结论、耗时、产品错误码与版本，不保留 PIN、会话链接或凭据。

1. 在独立验收主机上完成安装，使用此前未与该主机配对的测试客户端。不要删除现有设备的配对状态来冒充干净环境。
2. 从开始菜单打开产品，完成合法依赖部署和检查，启动后看到主机就绪。
3. 用户能在界面找到配对入口，并在等待期内完成一次新的配对；不需要修改注册表或手工复制证书。
4. 错误 PIN、超时与取消有明确反馈；恢复后可以重新配对，不留下永久忙态。
5. 客户端实际列出并启动一个明确支持的桌面或游戏，收到画面、声音及输入响应；正常退出后主机恢复可连接。
6. 产品重新启动后，同一客户端仍能按运行时承诺连接；另一个未授权客户端不能跳过配对。
7. 若提供解除配对，验证仅撤销指定测试客户端，其他客户端不受影响。

当前上述流程尚未执行。真实配对涉及受保护状态，仍须在具备合法运行时、专用验收环境和明确操作授权时实施。完整发布的其他条件见 [开源发布验收](release-readiness.md)。
