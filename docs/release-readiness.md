# 开源发布验收

截至 2026-11-07，本仓库处于发布准备阶段。源码测试可以从干净克隆运行；尚不能承诺新用户仅凭克隆即可完成串流。以下条件按实际交付物核验，不能用历史主机记录或夹具 MSI 代替。

## 必须完成的交付

| 条件 | 当前状态 | 完成依据 |
|---|---|---|
| 产品代码许可证 | 已加入 GPL-3.0-only | 根目录 LICENSE 与 LICENSING.md；第三方声明单独保留 |
| 源码测试与贡献说明 | 已有本地夹具测试与 Windows CI 配置 | 干净克隆的实际运行结果；远端 CI 首次执行仍未验证 |
| 首次使用说明 | 已有 quickstart 与只读依赖预检 | 新用户按文档准备依赖、部署、启动、配对、串流与停止；实机走读尚未完成 |
| 独立公开运行时包 | 未提供真实公开版本 | 版本、支持平台、产品兼容范围、真实下载地址、归档 SHA-256、文件清单 |
| 运行时许可和来源 | 待供应方提供 | 每个分发文件的来源、许可、归属及适用的对应源码和构建材料；独立打包不免除义务 |
| NVIDIA 自备组件 | 缺少完整公开准备说明 | 官方或其他有权供应方的合法取得渠道、适用版本和目录准备方式；不得将未知来源二进制作为依赖 |
| 新版真实构建与安装生命周期 | 未验收 | 同一版本 MSI 的干净 VM 安装、升级、修复、卸载和失败回滚；确认运行时进程与产品任务结果，保留用户状态与配对材料 |
| 首次配对及基本串流 | 新版本未验收 | 使用公开材料完成新客户端配对、至少一种明确支持的分辨率/编码串流、退出与再次启动 |
| 目录权限与运行协调 | 仍有缺口 | 处理用户会话写入路径后验证最小权限；验证 supervisor 与手动 Start/Stop 的交叉操作 |
| 发布内容与历史检查 | 工作区清理中 | 核查所有分发文件及拟公开的 Git 历史；不包含内部路径、私有链接、主机数据、运行时、凭据或二进制 |

签名计划见 [msi-signing.md](msi-signing.md)。尚未完成签名，不得声称发行包已签名或有可信发布者。是否提供未签名的预览版必须在该发行说明中明确；源码开源本身不依赖购买证书。HDR、AV1、环绕声、手柄和其他 GPU/驱动组合只列经过验证的支持范围，其余沿用兼容性矩阵中的未覆盖状态。

## 运行时供应方需要交付的信息

在提供下载链接之前，供应方应准备完整版本记录：运行时版本、归档文件名、支持的 Windows/架构、产品兼容范围、归档 SHA-256、逐文件清单、依赖安装说明、公开接口版本、来源与许可声明，以及所需的对应源码获取方式。产品侧接口见 [runtime-bundle-contract.md](runtime-bundle-contract.md)。

文件存在、哈希匹配或夹具测试通过，只能证明各自检查的条件，不能证明来源合法、行为兼容或已通过安全验收。不要用空文件或合成 helper 补成“发行包”。运行时包不得夹带 NVIDIA 二进制、配对状态、日志或凭据。

## 干净环境验收顺序

1. 从拟发布的确切源码版本取得完整克隆，按 [快速开始](quickstart.md) 运行预检和源码测试，记录版本与跳过项。
2. 从公开发行记录取得匹配运行时，核对 SHA-256 与许可材料；依适用许可单独准备组件树。
3. 在隔离 Windows VM 或专用验收机上构建并测试安装生命周期。真实串流还需要支持 GPU 和客户端的环境，普通 VM 的安装通过不能替代串流验收。
4. 按文档完成部署、Check、Start、人工配对、串流、退出和 Stop；验证托盘、支持包与失败恢复。
5. 对同一产物验证升级、修复、卸载与回滚。MSI 动作返回零或安装器退出成功不等于 runtime 停止和任务清理成功，必须核对最终状态。
6. 以最终 staging 文件重算发布清单哈希，记录源码提交、构建工具、依赖版本与实际覆盖范围。

## 源码公开方式

移出工作区的内部笔记仍可能存在于 Git 历史中。发布前必须检查将要公开的全部历史，或另行准备经过核验的干净源码快照并保留必要版权和许可信息。这里没有重写历史、推送分支或改变仓库可见性。

[路线图](product-roadmap.md) 跟踪完整产品工作；本表限定“新用户能够获得必要材料并按文档使用”的发布条件。尚缺真实依赖或实机证据时，发行状态必须保持未完成。
